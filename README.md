# КлючУчёт — информационная система учёта заказов мастерской ключей

**Дипломная работа:** «Разработка информационной системы учета заказов мастерской ключей».

«КлючУчёт» — проект внутренней веб-системы для мастерской по изготовлению, дублированию, ремонту и программированию ключей. Цель — перейти от бумажного учёта к учёту клиентов, услуг и заказов, контролю оплаты, статусов и выручки.

> **Текущее состояние:** архитектура согласована и подготовлена к реализации. Приложение (React/Express), Prisma-схема и миграции ещё **не написаны**. Этот репозиторий сейчас содержит документацию и безопасную заготовку структуры, а не запускаемую систему.

## Возможности первой версии (MVP)

- Вход администратора и сотрудника; JWT передаётся в заголовке `Authorization: Bearer <token>`.
- Управление клиентами: имя, телефон, история заказов.
- Каталог услуг: дубликаты обычных и автомобильных ключей, ремонт, программирование домофонных ключей.
- Обычный заказ с клиентом **или быстрый заказ без карточки клиента** (`clientId=null`).
- Выбор услуг и количества; расчёт итоговой суммы **на сервере в целых тенге**.
- Фиксация исторической цены услуги: изменение каталога не меняет старые заказы.
- Статусы: Новый → В работе → Готов → Выдан; предусмотрена отмена неоплаченного заказа.
- **Запрет выдачи без оплаты:** статус «Выдан» доступен только если заказ отмечен оплаченным.
- Поиск заказов, журнал изменений, статистика количества заказов/статусов и оплаченной выручки.
- Управление сотрудниками и ценами только администратором.

## Как будет запускаться проект

**Сейчас запускать нечего:** каталог `client/` и приложение внутри `server/` будут заполнены на следующем этапе. После реализации установка будет включать:

1. Установку Node.js (совместимой LTS-версии) и PostgreSQL.
2. Копирование `server/.env.example` в `server/.env`, замену тестовых значений реальным адресом БД и собственным секретом JWT.
3. Установку зависимостей отдельно для `server/` и `client/` командой `npm install` (после создания соответствующих `package.json`).
4. Применение миграций Prisma и заполнение демонстрационными данными (после добавления Prisma-схемы и seed-скрипта).
5. Запуск серверной и клиентской частей через скрипты `npm run dev` (после их определения в `package.json`).

Конкретные команды миграций и запуска будут добавлены в README, **когда появится рабочий код**. Нельзя выдавать документацию за готовое приложение.

## Пользователи и безопасность

- Роли: `ADMIN` (администратор), `EMPLOYEE` (сотрудник). Регистрации через сайт нет.
- Пароли на сервере будут храниться только как хеши.
- Во всех защищённых HTTP-запросах используется Bearer JWT; роль и `isActive` проверяются на сервере.
- Токен планируется хранить в `sessionStorage` на время работы вкладки; выход очищает токен на клиенте. В производственной системе необходимо учитывать риск XSS и использовать HTTPS.
- `.env`, пароли, секреты, `node_modules/` и сборки в Git не добавляются.
- Для демонстрации используются вымышленные персональные данные.

## Порядок реализации

1. Создать React/Vite и Node/Express приложения, настроить их взаимодействие.
2. Спроектировать и создать модели PostgreSQL/Prisma и миграции.
3. Реализовать вход, проверку JWT и роли.
4. Реализовать клиентов, каталог услуг, управление сотрудниками.
5. Реализовать обычный и быстрый заказ, расчёт стоимости, сохранение цен.
6. Реализовать статусы, оплату, **запрет неоплаченной выдачи**, журнал событий.
7. Добавить интерфейс списков, поиска, карточек, статистики; провести тесты из архитектуры.

## Границы проекта

В MVP не входят: онлайн-оплата, фискальные чеки, возвраты, несколько филиалов, склад заготовок, SMS-уведомления, личный кабинет клиента и полноценная бухгалтерия. Расчёт «выручки» — сумма заказов, отмеченных оплаченными, а не данные официальной кассовой системы.
